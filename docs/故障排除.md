# 故障排除

> 所有运行日志在程序目录 `logs\dsh_yyyyMMdd.log`，排查问题时先看日志。

## 1. 程序无法启动 / 双击无反应

- 确认已安装 .NET 8 Desktop Runtime（框架依赖发布时必需）
- 查看 `logs\` 下是否有 FATAL 日志
- 确认没有第二个实例在运行（本程序有单实例保护）

## 2. 提示"语音识别失败 HTTP 401"

- API 密钥错误或已失效：检查设置窗口/`appsettings.json` 中的 `ApiKey`
- 使用了环境变量 `DSH_API_KEY` 时，以环境变量为准

## 3. 提示"DSH 调用失败 HTTP 404"或 InvalidParameter

- `DSHModel`（如 `deepseek-v4-flash`）在你的百炼工作台不可用
- 打开百炼控制台 → 模型广场，确认已开通该模型，修改 `Config\appsettings.json` 后重启

## 4. 语音识别失败 HTTP 400/404

- `SpeechModel` 不是工作台可用模型（默认 `qwen3.5-omni-flash`）；用
  `GET {ApiHost}/models` 查看可用模型
- 注意：百炼 compatible-mode 没有 `/audio/transcriptions` 路由，转写走原生多模态网关
- 音频为空：说话太短，或麦克风被静音

## 5. 唤醒词不灵敏 / 不触发

- 默认使用**本地识别**（`WakeMode=local`）：确认日志出现
  "本地唤醒词检测已启动"，否则说明系统缺少语音识别引擎，会自动回退云端识别
- 本地引擎误判/漏判时，可在设置中调整唤醒词变体（如识别为"尔苟"时加入该变体）
- 若使用云端识别（`WakeMode=api`）：调低 VAD 阈值（设置 → VAD 阈值，默认 0.02，
  可降到 0.01）；缩短"静音结束判定"（默认 1200ms）可更快触发
- 兜底：用 `Win+F2` 快捷键唤醒（任何模式可用）

## 6. 语音识别正常但 DSH 回复奇怪

- 检查 `DSHModel` 是否为对话模型（不要用纯 ASR 模型）
- 查看日志中"DSH 原始返回"与"DSH 指令"，确认模型输出是否符合协议
- 可调整 `DSHCommandService.cs` 中的系统提示词

## 7. 语音回复没有声音

- 默认云端 TTS（`TtsMode=cloud`）：确认网络可用、`TtsModel`/`TtsVoice` 是工作台可用
  模型与音色（qwen3-tts-flash 支持 Cherry/Serena/Ethan/Noah 等）；失败会自动回退本地，
  日志会记录"云端 TTS 失败，回退本地语音"
- 检查系统音量未静音；本地模式确认安装了中文语音包：
  设置 → 时间和语言 → 语音 → 添加"简体中文"语音
- 检查设置中"语速/音量"是否被调到了极端值（仅本地模式生效）

## 8. 打开应用/网址失败

- `open_app` 的 target 必须是程序名（在 PATH 中）或完整路径
- 确认 Windows 默认浏览器/关联程序正常（ShellExecute 依赖系统关联）

## 9. 系统命令（关机等）不执行

- `system_command` 支持：shutdown/restart/lock/sleep/hibernate/logoff（及中文别名）
- 若 DSH 返回其它写法，指令会被拒绝并语音提示"不支持的系统操作"

## 10. 长时间运行内存增长

- 波形队列上限 64 帧、历史记录上限 20 条，均有上限约束
- 若仍异常增长，导出 `logs\` 日志反馈开发者

## 11. 快捷键 Win+F2 无效

- 确认设置中"启用全局快捷键"勾选
- 该组合可能被其它程序占用（日志会有"注册全局快捷键失败"），换用托盘菜单"立即对话"

## 12. 云端识别消耗额度过快

- 默认 `WakeMode=local` 时唤醒检测完全免费；仅指令识别消耗额度
- 若设置为 `WakeMode=api`：环境噪音大时会频繁触发识别——调高 VAD 阈值、
  调大"静音结束判定"；日常使用建议改回本地唤醒或仅用快捷键
