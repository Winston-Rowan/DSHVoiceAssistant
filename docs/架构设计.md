# 架构设计

## 一、总体架构

```
┌─────────────────────────── Diva 应用（WPF，本地） ───────────────────────────┐
│                                                                              │
│  ┌─────────────┐   ┌──────────────┐   ┌────────────────┐   ┌──────────────┐  │
│  │ AudioCapture │──▶│ VoiceActivity │──▶│ SpeechRecognition│   │  TTSService  │  │
│  │   (NAudio)   │   │   Detector    │   │  (百炼ASR)      │   │  (SAPI5)     │  │
│  └──────┬──────┘   └──────┬───────┘   └───────┬────────┘   └──────┬───────┘  │
│         │                 │                   │                    │          │
│         ▼                 ▼                   ▼                    ▼          │
│  ┌──────────────────────────── DivaOrchestrator（状态机）───────────────────┐ │
│  │  Idle → Recording → Transcribing → Thinking → Executing → Speaking    │ │
│  └───────┬───────────────────────┬───────────────────────┬───────────────┘ │
│          │                       │                       │                 │
│          ▼                       ▼                       ▼                 │
│  ┌─────────────┐        ┌──────────────┐         ┌──────────────┐          │
│  │ WakeWordService│      │ DSHCommandService│       │ CommandProcessor│      │
│  │ (API唤醒检测) │      │ (DSH指令引擎)  │       │ (本地执行器)   │          │
│  └─────────────┘        └──────────────┘         └──────────────┘          │
│                                                                              │
│  MainWindow / MainViewModel / TrayIconService / HotKeyService（表现层）      │
└──────────────────────────────────────────────────────────────────────────────┘
```

设计原则：**一切指令决策交给 DSH 引擎（大模型 + 系统提示词），本地只做采集、展示与落地**。
所有服务通过接口（`I*`）定义并经依赖注入装配（`App.xaml.cs`），便于替换实现
（如把 NAudio 换成其它采集库、把唤醒方案换成 Porcupine）。

## 二、核心模块

| 模块 | 职责 | 关键实现 |
|------|------|----------|
| `AudioCaptureService` | 麦克风采集 | NAudio `WaveInEvent`，16kHz/16bit/单声道，每 100ms 一帧 |
| `VoiceActivityDetector` | 语音活动检测 | 基于 RMS 能量的 VAD：连续有声帧判定开始，静音超时判定结束 |
| `WakeWordService` | 唤醒词检测 | VAD 分段 → 百炼 ASR → 文本匹配唤醒词变体（diva/迪瓦/迪娃…） |
| `SpeechRecognitionService` | 指令语音识别 | 百炼原生多模态网关（base64 音频转写，omni 模型） |
| `DSHCommandService` | ⭐ DSH 指令引擎 | 百炼 `/chat/completions` + DSH 系统角色提示词 → 结构化指令 |
| `CommandProcessor` | 本地执行器 | 打开应用/搜索/系统命令/文件操作/媒体键/PowerShell |
| `AppFinder` / `AppInventory` | 应用/游戏智能查找与软件归档 | 桌面/开始菜单快捷方式、注册表卸载项、App Paths、Steam/Epic 库 → 软件清单 JSON+MD；名称智能匹配（去平台噪音+前缀序号启发式） |
| `TTSService` | 语音合成 | 云端 qwen3-tts-flash 自然音色（失败回退本地 SAPI），NAudio 播放 |
| `DivaOrchestrator` | 状态编排 | 串联全流程状态机，见下 |
| `TrayIconService` | 系统托盘 | WinForms NotifyIcon，图标颜色随状态变化 |
| `HotKeyService` | 全局快捷键 | RegisterHotKey，Ctrl+Alt+D 唤醒 |
| `ConfigService` | 配置读写 | `Config\appsettings.json` + `DIVA_API_KEY` 环境变量覆盖 |

## 三、状态机

```
                    唤醒词 / Ctrl+Alt+D
   ┌────────┐  ───────────────────────────▶  ┌───────────┐
   │  Idle  │                                │ Recording │   VAD 一句话结束
   │ 待命中  │ ◀── 3秒后自动恢复 ──┐           └─────┬─────┘  或 超时(15s)
   └────────┘                     │                 │
        ▲                         ▼                 ▼
        │                  ┌───────────┐     ┌──────────────┐
        │                  │  Error    │     │ Transcribing │──▶ Thinking(DSH)
        │                  │   出错    │     └──────────────┘        │
        │                  └───────────┘                             ▼
        │                        ▲                            ┌──────────┐
        │                        │ 任意环节失败                │ Executing │
        │                        └────────────────────────────│   执行    │
        │                                                     └────┬─────┘
        └────────────────────────── TTS 回复完成 ◀─── Speaking ◀──┘
                                                      (TTS朗读response)
```

要点：

- **唤醒词接管**：唤醒词与指令一气呵成（"Diva 打开记事本"）时，编排器直接接管当前
  录音片段，并在送 DSH 前剥离句首唤醒词
- **互斥保护**：处理指令期间关闭唤醒检测（`_wake.IsEnabled`），防止重复唤醒；
  单条指令流水线用 `_processing` 互斥
- **静音**：静音即暂停采集与唤醒，恢复后回到待命

## 四、线程模型

| 线程 | 处理内容 | 说明 |
|------|----------|------|
| NAudio 回调线程 | 音频帧 → RMS → VAD → 字节积累 | 轻量操作，不做 IO/网络 |
| ThreadPool | ASR / DSH / 本地执行 / TTS 等待 | 异步流水线 `ProcessUtteranceAsync` |
| UI 线程（Dispatcher） | 界面状态更新 | ViewModel 通过 `SynchronizationContext.Post` 封送 |
| TTS 事件线程 | SpeakCompleted | 代际计数（generation）丢弃过期事件 |

共享数据（录音片段、状态）以 `lock` / `SemaphoreSlim` 保护；
波形控件内部使用线程安全队列（`lock + Queue<float>`），UI 定时器负责重绘。

## 五、唤醒词方案（三种，可切换）

1. **本地识别（默认，`WakeMode=local`，零 API 算力）**：
   `LocalWakeWordService` 采用**滑动窗口批量识别**：保留最近约 4 秒的麦克风 PCM，
   每 2 秒把窗口快照（完整数据）交给 Windows 内置 SAPI 识别引擎
   （`System.Speech.Recognition`）识别一次，词表 Grammar 为
   （迪娃/Diva/迪瓦/黛娃/蒂娃）。
   优点：完全离线、免费；引擎不直接访问麦克风（MemoryStream 喂入），与 NAudio 无设备冲突。
   注意：SAPI 流输入只认"启动时已知长度"的流（实测确认），因此不能实时喂入，
   必须采用窗口快照方案；带 RMS 门控，静音时跳过识别。
2. **云端识别（`WakeMode=api`）**：`WakeWordService` 用 VAD 分段 → 云端 ASR → 文本匹配唤醒词。
   每次说话消耗一次识别额度；本地唤醒引擎不可用时自动回退到该方案。
3. **快捷键（`Ctrl+Alt+D`）**：零成本、零延迟，任何模式下可用。

**扩展点**：唤醒服务按 `IWakeWordDetection` 接口实现，DI 中以
`AddKeyedSingleton<IWakeWordDetection, ...>("local"/"api")` 注册，
编排器按配置选择，本地失败自动回退云端。

## 六、DSH 引擎的决策边界

`DSHCommandService.SystemPrompt` 定义了 DSH 引擎的全部能力面：

- 8 类动作的转换规则与 JSON 输出格式
- 输出约束（只输出 JSON、回复简洁友好、10~30 字）
- 失败兜底（无法理解的指令 → text_reply 请用户重说）

解析层（`DivaCommandParser`）对模型输出做了防御：
Markdown 围栏剥离、括号配对扫描、无 JSON 时降级为文本回复。
这使得即使模型输出格式漂移，应用也不会崩溃。

## 七、安全设计

| 风险 | 缓解 |
|------|------|
| API 密钥泄露 | 支持环境变量覆盖；README 建议公开仓库不落密钥 |
| 误删文件 | `file_operation delete` 必须携带 `confirm=true` 参数才执行 |
| 任意脚本执行 | `custom_script` 走 PowerShell 但带 60 秒超时与完整日志 |
| 语音误唤醒 | VAD 阈值 + 连续帧防抖 + 唤醒词变体白名单 |
| 应用崩溃 | 全局异常兜底（DispatcherUnhandledException 等）+ 日志落盘 |
